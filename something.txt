# Usage符号
这些符号是“格式说明”，不是要你原样输入：
符号	含义
[]	可选，可写可不写
<> 或大写单词	必填占位符，比如 FILE、DIRECTORY
...	可以重复多个
|	或者，二选一
{}	分组
--	选项结束，后面都当文件名

# Options部分
-a, --all                表示短选项 -a 和长选项 --all 等价
-l                       表示只有短选项
-o FILE, --output=FILE   表示这个选项后面要带参数

origin          远程仓库名称
HEAD            当前本地分支最新提交
swerve_hero     远程目标分支名称

git switch -c swerve_hero在本地新建立远程跟踪分支
之后只需要git push -u origin swerve_hero

(HEAD：是一个特殊指针，永远指向你当前正在工作的本地位置。
main：是本地仓库的一个分支指针，指向该分支的最新提交。
合起来 HEAD -> main：表示 “我当前正处在本地 main 分支上，并且 main 指向这个提交”)
(HEAD（不带 ->）：表示你处于“分离头指针（Detached HEAD）”状态，没有分支指向这个提交，你只是临时来看一眼这个历史版本)
HEAD->swerve_hero:当前所在的本地分支

(origin/main 是一个远程跟踪分支（Remote-tracking branch）。
它不是你手动创建的，而是当你执行 git fetch 或 git push 时，Git 自动更新的。
本质含义：“上一次和远程仓库 origin 通信时，origin 上 main 分支的位置快照。”)
origin/swerve_hero:远程跟踪分支;本地保存的远程跟踪分支(refs/remotes/origin/swerve_hero)因为它只是最后一次同步时的记录，所以远程服务器可能已经发生变化,使用git fetch origin main更新当前远程状态

(origin/HEAD 是一个符号引用（Symbolic Reference），它指向远程仓库 origin 的“默认分支”（也就是你在 GitHub/GitLab 仓库页面上看到的默认分支，通常是 main 或 master）。
它的作用类似于一个“路标”，告诉你：“如果你不带参数 git clone 这个远程仓库，默认会检出哪个分支？”
查看它指向哪：执行 git remote show origin，你会看到第一行 HEAD branch: main。这就是 origin/HEAD 在告诉你的信息
实际规则：绝大多数情况下，origin/HEAD 都指向 origin/main（即 origin/HEAD -> origin/main）。如果你在括号里看到 origin/HEAD，它只是跟着 origin/main 的一个“软链接”)
origin/HEAD:远程默认分支

本地领先于远程
a1b2c3d (HEAD -> main) 新增了功能
e4f5g6h (origin/main, origin/HEAD) 旧版本

远程领先于本地
a1b2c3d (origin/main, origin/HEAD) 队友的新功能
e4f5g6h (HEAD -> main) 我本地的旧版本

###proxy代理
你不直接访问目标网站，而是把请求先发给代理服务器，由代理服务器替你去访问，再把结果返回给你
PROXY_HOST='192.168.250.2'
PROXY_PORT='7897'

curl --noproxy '' --proxy "http://192.168.250.2:7897" -I --max-time 15 https://www.google.com
--noproxy 用来指定“哪些主机不要走代理”,写了空字符串后，就强制所有目标都使用下面的代理
--proxy 指定代理服务器,使用 192.168.137.1 这台机器上的 7897 端口作为 HTTP 代理
-I 等价于 --head,只发送 HEAD 请求，只获取响应头，不下载网页正文
--max-time 表示整个请求最多允许持续 15 秒
